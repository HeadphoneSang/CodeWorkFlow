# 前端页面用 file:// 打开会让 fetch/module 全部失效
trigger: 用户报告"前端请求失败/上传失败"但后端 curl 冒烟正常，或页面点击无反应/表单原生提交刷新
scope: 全部（任何 fetch 相对路径 + ES module 的前端项目）

## 错误表现
后端接口 curl 验证全部 200，但用户浏览器里点上传就失败或页面直接刷新、无任何请求发出。

## 正确做法
1. 先确认用户浏览器地址栏是什么协议：`file:///` 还是 `http://`。
2. 若是 `file://`：让用户改从后端静态挂载地址访问（本项目是 http://127.0.0.1:8000/）。
3. 排查顺序建议：先 curl 后端接口 → 再 curl 静态页/JS 模块 → 再问打开方式，能快速二分定位是服务端还是使用方式问题。

## 原因
- `<script type="module">` 在 file:// 协议下被浏览器 CORS 策略直接拦截，JS 不加载、事件不绑定。
- `fetch('/upload')` 相对路径在 file:// 下解析为 `file:///upload`，必然失败。
