# Agent Code Workflow — 多智能体状态共享工作流

一个**标准工作流工作区**：让 Claude Code、Codex 等多个 AI 编码智能体在同一台机器上并行开发同一个项目时，通过一套纯 Markdown 的状态文件实现**项目隔离、需求隔离、状态共享**。

本目录只存放状态与上下文，**不存放项目源码**——源码始终在各自的「真实项目目录」里。

## 它解决什么问题

多个智能体（如 Claude Code 写前端、Codex 写后端）并行开发时互不知情：不知道项目进行到哪、接口约定是什么、对方正在做什么。本工作流用一套约定好的状态文件作为智能体之间的"共享内存"：

- 前端智能体实现完登录表单，把状态和接口契约写进工作区；
- 后端智能体启动时读到契约，照着前端已定的接口实现后端；
- 全程靠文件交接，不需要人工传话。

## 快速开始

1. 在智能体（Claude Code / Codex 等）中打开本目录开启会话；
2. 适配层（`CLAUDE.md` / `AGENTS.md`）自动路由到统一提示词 `AGENT_GUID.md`；
3. 智能体列出 `./workspace/` 下的已有项目供你选择，或选择**新建项目**（需提供项目名 + 真实项目目录，自动 `git init`）；
4. 之后的一切行为都由 `AGENT_GUID.md` 约束。

## 目录结构

```
agent_code_workflow/
├── AGENT_GUID.md               # ★ 唯一提示词来源（所有智能体统一遵循）
├── CLAUDE.md                   # Claude Code 适配层：只路由，不存内容
├── AGENTS.md                   # Codex 适配层：只路由，不存内容
├── knowledge/                  # 跨项目共享的经验知识库（按需加载）
│   ├── INDEX.md                #   经验索引：会话启动只加载这一个
│   └── lessons/*.md            #   经验正文：任务命中触发条件才读
└── workspace/                  # 状态工作区
    └── <项目名>/
        ├── PROJECT.md          # 项目全局执行路径（需求进度表 + 当前焦点）
        └── <需求ID>/           # 每个需求一个隔离分区，如 001-user-login/
            ├── STATUS.md       #   各角色执行状态（兼认领锁）
            ├── CONTRACT.md     #   前后端接口契约（握手文件）
            └── LOG.md          #   追加式交接日志（只追加不改写）
```

## 核心机制

### 1. 两级隔离

| 层级 | 目录 | 作用 |
|---|---|---|
| 项目隔离 | `workspace/<项目名>/` | 项目之间互不干扰 |
| 需求隔离 | `workspace/<项目名>/<需求ID>/` | 每个需求独立的状态上下文，可并行推进 |

### 2. 多智能体协作协议

- **认领锁**：`STATUS.md` 中每个角色一行，`owner=<工具>:<角色>` 认领后其他智能体可见且不抢占；每个智能体只改自己那一行。
- **契约先行**：跨角色接口先写 `CONTRACT.md` 再各自实现；接口变更走「追加变更 + 对方确认」流程。
- **日志只追加**：`LOG.md` 永不改写历史，交接全程可追溯且无写冲突。
- **先读后写**：状态文件可能被并发修改，编辑前先重新读取，做最小改动。

### 3. Git 硬性纪律（每个需求必须遵守）

0. 新需求从 `main` 开 `feature/<需求ID>` 分支，禁止直接在 main 上开发；
1. 每完成一个小功能点立即 commit，实现路径可追溯；
2. 每次实现后智能体自写单元测试，**全部通过后停下等待用户 Code Review**，通过才继续；
3. 合回 `main` 由用户决定，智能体不自行 merge / push。

### 4. 经验沉淀（按需加载的知识库）

重复踩的坑（如 Windows 上按 Linux 习惯跑命令）会被沉淀为经验条目：

- 会话启动**只加载** `knowledge/INDEX.md`（每条一行，占用极小）；
- 任务命中某条经验的触发条件时，才读取对应正文；
- 同类错误出现 ≥2 次、错误可复现、或被用户纠正时，智能体必须沉淀新条目或修正旧条目。

## 状态流转

```
TODO → DOING → (实现 → 自测通过) → REVIEW（等用户） → DONE
                  ↓
               BLOCKED（写 blockers，LOG 说明）
```

需求状态汇总在 `PROJECT.md` 的进度表中，`current_focus` 字段标明当前焦点，任何智能体启动时一眼可知项目进展。

## 提示词分层

| 文件 | 角色 |
|---|---|
| `AGENT_GUID.md` | 唯一提示词来源，所有规则都在这里 |
| `CLAUDE.md` / `AGENTS.md` | 各工具的适配层，只做一行路由指向 `AGENT_GUID.md`，冲突时以 `AGENT_GUID.md` 为准 |

改工作流规则 = 只改 `AGENT_GUID.md`，所有接入的智能体同步生效。
